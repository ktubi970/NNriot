# NNriot project summary

NNriot is a League of Legends data and prediction application. Riot match collection writes to a configurable SQLite source. The Flask app serves player history, prediction routes, retrospective analytics, and existing Jinja pages from `templates/`. On 9 October 2026 the React/Vite frontend, npm configuration, browser tests and Playwright workflow were restored to their original paths. Flask serves the redesigned responsive cockpit at `/` and retains the Jinja dashboard at `/dashboard`. The original source snapshot remains under `archive/frontend-2026-10-09/`. The cockpit starts with an empty draft, displays the service's raw/calibrated probabilities and abstention contract, and reports API failures without invented predictions, statistics or explanations. Dialogs support keyboard navigation, focus restoration and reduced motion. Live/OCR imports are explicitly unavailable pending real endpoint support.

The operational schema is version 16, read from `schema_version` (not `PRAGMA user_version`, which is 0 on the examined source). v13 added player spatial embeddings; v14 migrated the crawler queue; v15 records the pinned encoder (`encoder_id`) of each spatial embedding; v16 records when each match was ingested (`ingested_at`) and whose match list returned it (`fetched_by_puuid`). Migrations remain governed by `docs/database_merge.md`. `matches` retains compressed Riot payloads, `match_participants` supports indexed player history, and `training_dataset` stores features and labels. Player names and aliases live in separate tables. `analytics/` reads the operational source and builds a separate, rebuildable SQLite evidence mart. Analytics reports post-match associations with traceable evidence; it does not establish causality or pre-match model quality.

`python cli.py train` runs candidate pre-match training from the configured source. The candidate uses draft and game-context inputs, chronological train/validation/test partitions, and a saved split manifest and metrics report. It does not automatically replace the active application checkpoint. The older continuous loop remains available as `python cli.py train-continuous`. See [docs/pre_match_training.md](docs/pre_match_training.md) for the protocol and its limits.

The database merge tool uses explicit source, target, staged output, and report paths. It preserves the newer target's conflicting records and archives excluded or conflicting old data before old databases are removed. The [merge guide](docs/database_merge.md) covers validation and publication. Runtime paths come from `NNRIOT_DB_PATH` and `NNRIOT_ANALYTICS_DB_PATH`; the example file under `runs/` is a local deployment choice.

Install Python dependencies with `pip install -r requirements.txt` and frontend dependencies with `npm ci`. Build the cockpit with `npm run build`, then start Flask with `python cli.py web`; `npm run dev` provides Vite hot reload with Flask running in a second terminal. Python tests live in `tests/`. Frontend checks use `npm run typecheck`, `npm run test:unit` and `npm run test:e2e`. The default browser suite runs against an isolated Vite server with mocked APIs across desktop, tablet and mobile; it does not start Flask, collection or training. The earlier browser tests remain an explicit opt-in through `npm run test:e2e:legacy` and include demonstration assertions and manual training.

The fixed serving reference is `runs/candidate_deepsets_v3/model.keras` with contract `nnriot.players14.v1` and a SHA-256-bound manifest in `docs/model_serving/reference.manifest.json`. Its training bounds and calibration are unknown/absent; the legacy checkpoint has no separate composition head or map-side bias. The facade validates artifacts and input layouts, uses shared result-end ordered player history, separates raw/calibrated probabilities and forces abstention without calibration and independent serving validation. 18D timeline inputs require an available historical source; 46D spatial models are excluded pending encoder provenance.

A frozen recent common-cohort comparison is in `runs/served_model_comparison_20261009_complete/`: 2,000 matches from 16–17 September 2026, full initial/intersection coverage accounting, consistent winner metrics, selective error/Wilson curves and paired moving-block bootstrap intervals. The comparison is exploratory because a recent independent test cannot be established for all candidate training pipelines. It does not promote a model or retune thresholds on test. Reproduce using `python -m scripts.compare_served_candidates --replay runs/served_model_comparison_20261009_complete --output-dir runs/new_replay`; see `docs/model_serving/README.md` for limitations and verification.
